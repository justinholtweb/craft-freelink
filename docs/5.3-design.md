# FreeLink 5.3 — design

Status: implemented on `feature/5.3.0` (Craft 5). This document is the reference for the Craft 6
port: it describes *what* FreeLink 5.3 stores, exposes and guarantees, and *why*, in terms that do
not depend on Yii. Craft 5 class names are given where they help locate the code.

## 1. Goals and non-goals

Goals (owner's list, in order):

1. A FreeLink CP section with a customisable sidebar item (label, icon from Craft's icon picker, or
   a pasted SVG that is sanitised).
2. A **Links** screen listing every FreeLink link on the site, filterable and paginated, efficient
   on large sites.
3. Reverse lookups everywhere: Links screen ("what links to this element"), a sidebar panel on
   element edit screens, a service method, and Twig.
4. Broken-link checks: element links (from the database only) and URL links (over HTTP, from a
   queue job or console command, with strict SSRF protection).
5. Migration tools moved into the CP section, old URL redirected.
6. An optional icon per link.
7. GraphQL mutations for FreeLink fields, and a reverse-lookup query, respecting schema scope.
8. MCP tools on Craft 5.12+'s MCP server.

Non-goals:

- No crawler. Only URLs stored in FreeLink fields are ever fetched. Nothing that comes from a
  request, a GraphQL argument or an MCP argument is ever used as a URL to fetch.
- No change to how link *values* are stored (JSON in the content column, element targets in
  `freelink_links`). 5.3 adds an index beside them; it never becomes the source of truth.
- No Vue in the CP. Twig + Craft's forms macros + small vanilla/Garnish JS, like the field UI.

## 2. Data model

### 2.1 Unchanged

- Field value JSON in `elements_sites.content` (Craft 5) keyed by the layout element UID. One
  object (single mode) or a list (multi mode). Element links store `"value": null`.
- `freelink_links` — element-link targets, keyed by `(fieldId, ownerId, ownerSiteId, sortOrder)`.
  Written for *every* save (drafts and revisions included) because it is what loads the value.
- `freelink_migrations` — migration history.

### 2.2 New: link JSON key `icon`

Each link object may carry `"icon": "<name>"` — a Font Awesome icon name from Craft's bundled set
(`src/icons/index.php`), e.g. `"arrow-up-right-from-square"`. Missing or `null` means no icon.
Written only when the field's **Allow icons** setting is on (see §8). Old values without the key
load as `null`; no data migration is needed.

### 2.3 New table: `freelink_index`

A denormalised, query-friendly copy of every link in **live content** (one row per link). It is
derived data: it can be dropped and rebuilt at any time from the field values.

| Column        | Type                 | Notes |
|---------------|----------------------|-------|
| `id`          | pk                   | |
| `fieldId`     | int, FK `fields` CASCADE | |
| `ownerId`     | int, FK `elements` CASCADE | the element whose field holds the link (may be a nested entry) |
| `ownerSiteId` | int, FK `sites` CASCADE | |
| `rootOwnerId` | int, FK `elements` CASCADE | `ElementHelper::rootElement($owner)->id`; the element an editor opens |
| `sortOrder`   | smallint             | position in the field (0-based) |
| `type`        | varchar(64)          | link type handle |
| `isElement`   | bool                 | element link type? |
| `targetId`    | int null, FK `elements` SET NULL | element links only |
| `targetSiteId`| int null, FK `sites` SET NULL | |
| `url`         | text null            | non-element links: the URL as `Link::getUrl()` returns it (suffix applied, unsafe schemes already nulled) |
| `urlHash`     | char(40) null        | `sha1(url)`, joins to `freelink_checks` |
| `host`        | varchar(255) null    | lower-cased host of `url` for http(s) URLs, else null |
| `label`       | varchar(255) null    | link text as stored (truncated) |
| `dateCreated`, `dateUpdated`, `uid` | | |

Indexes: `(fieldId)`, `(ownerId, ownerSiteId)`, `(rootOwnerId)`, `(type)`, `(targetId)`,
`(host)`, `(urlHash)`.

**What is "live content"?** A row is written only when the owner *and* its root owner are neither
drafts nor revisions (`ElementHelper::isDraftOrRevision()` on both). Saving a draft does not touch
the index; applying it saves the canonical element, which reindexes. Trashed owners keep their rows
(restoring brings them back) and are filtered out at query time by joining `elements.dateDeleted`
for both owner and root owner.

Write path (`FreeLinkField::afterElementSave()` → `services\LinkIndex::indexValue()`): delete the
rows for `(fieldId, ownerId, ownerSiteId)`, insert one per non-empty link. One `DELETE` + one
batch `INSERT` per field per save.

Backfill: `services\LinkIndex::rebuild()` / the `freelink\jobs\IndexLinks` batched queue job /
`php craft freelink/links/reindex`. It walks every non-draft, non-revision, non-trashed element in
a field layout that contains a FreeLink field, per site, and reindexes its FreeLink values. The
5.3 migration queues it once. The Links screen shows a notice while the index has never been built.

### 2.4 New table: `freelink_checks`

One row per distinct checked URL (deduplicated by `urlHash`, so a URL used in 400 entries is
fetched once).

| Column      | Type         | Notes |
|-------------|--------------|-------|
| `id`        | pk           | |
| `urlHash`   | char(40) unique | |
| `url`       | text         | |
| `status`    | varchar(16)  | `ok`, `redirect`, `broken`, `error`, `blocked`, `skipped` |
| `httpCode`  | smallint null| final response code |
| `finalUrl`  | text null    | after redirects, when different |
| `redirects` | tinyint      | hops followed |
| `error`     | varchar(255) null | human-readable reason (never a response body) |
| `checkedAt` | datetime     | |
| `dateCreated`, `dateUpdated`, `uid` | | |

Rows for URLs no longer in the index are deleted by the check job (orphan sweep).

### 2.5 Migration and schema version

- `Plugin::$schemaVersion` `1.0.0` → `1.1.0`.
- `migrations/m261119_000000_link_index_and_checks.php` creates both tables if missing and pushes
  `IndexLinks`.
- `migrations/Install.php` creates all four tables for fresh installs.
- `safeDown()` drops the two new tables (they hold only derived data).

## 3. Plugin settings

`models\Settings` (stored in project config like any plugin's settings; edited at
**Settings → Plugins → FreeLink**, which is also linked from the section's subnav). Every setting is
optional — nothing is `required`, so a fresh install can always save.

| Setting | Type / default | Notes |
|---|---|---|
| `navLabel` | `?string` null | sidebar label; empty = plugin name. ≤ 64 chars |
| `navIcon` | `?string` null | icon name from Craft's icon picker (`Cp::iconPickerFieldHtml`). Must match `^[a-z0-9-]+$` and exist in Craft's icon set |
| `navIconSvg` | `?string` null | pasted SVG. Must be a single `<svg …>` element (≤ 50 KB). Stored as entered; **sanitised every time it is drawn** with `Html::svg($svg, sanitize: true, namespace: true)`. Wins over `navIcon` |
| `showReverseLookupPanel` | bool true | the "Linked from" panel on element edit screens |
| `enableExternalChecks` | bool true | off = URL links are never fetched; element-link status still works |
| `recheckAfter` | int 24 (hours) | a URL checked more recently is skipped unless forced |
| `hostDelay` | int 1000 (ms) | minimum gap between two requests to the same host |
| `maxChecksPerRun` | int 500 | URLs one job/command run fetches at most |
| `checkAllowedHosts` | string[] [] | **config file only** (`config/freelink.php`). Hosts allowed to resolve to private addresses (intranet links, local testing). Exact host match, no wildcards |
| `checkAllowedPorts` | int[] [80, 443] | **config file only**. Ports a checked URL may use |

The two config-only settings are not rendered in the CP and are dropped from POSTed settings, so
nobody with CP access can widen what the checker reaches.

Sidebar item: `Plugin::getCpNavItem()` applies label → SVG → icon in that order. Craft 5 has no
built-in nav customisation; a nav-customisation plugin (e.g. Verbb CP Nav) or Craft 6's own nav
editor overrides whatever FreeLink returns, and that is intended.

## 4. Permissions

Registered under a **FreeLink** heading:

| Permission | Grants |
|---|---|
| `accessPlugin-freelink` | (Craft's own) see the section |
| `freelink:viewLinks` | Links screen, reverse-lookup panel, stored check results |
| ↳ `freelink:checkLinks` (nested) | queue link checks / rebuild nothing else |

Admin-only (`requireAdmin()`; and `allowAdminChanges` where project config changes): migration tools
(they change field types), rebuilding the index, plugin settings.

The section's sidebar item is shown when the user has `accessPlugin-freelink`; each subnav item is
shown only with its own permission.

`hasCpSection = true`, `hasCpSettings = true`.

| URL (under `admin/`) | Controller action | Gate |
|---|---|---|
| `freelink` | redirect → `freelink/links` (or migrations for admins without other access) | `accessPlugin-freelink` |
| `freelink/links` | `links/index` | `freelink:viewLinks` |

| `settings/plugins/freelink` | Craft's plugin settings | admin + allowAdminChanges |

### Links screen

Server-rendered table (`_includes/pagination`, 50 per page), filters as GET params so every view is
linkable:

- `type` (link type handle), `field` (field id), `site` (site id, multi-site only),
  `source` (element type of the root owner) and `section` (entry section of the root owner),
  `domain` (host; matches the host and its subdomains), `status`
  (`all` / `problems` / `ok` / `unchecked`), `target` (element id — the reverse lookup).
- Columns: **Source** (root owner chip, linked to its edit page; nested owner noted), **Field**,
  **Type**, **Target** (element chip, or the URL as an external link with `rel="noopener noreferrer"`),
  **Status** (status dot + label: element status, or last check result with code and time).
- Query: one indexed `SELECT` over `freelink_index` joined to `elements` (owner, root owner,
  target), `elements_sites` (target), `entries` (root owner section, target post/expiry dates) and
  `freelink_checks`, plus one `COUNT(*)`. Source and target elements are then loaded in one query
  per element type + site for the 50 rows on the page.
- Actions: "Check links now" (`freelink:checkLinks`), "Rebuild index" (admin).

### Reverse-lookup panel

`Element::EVENT_DEFINE_SIDEBAR_HTML` on every element type. Shown when the setting is on, the user
has `freelink:viewLinks`, and the element (or its canonical) has at least one incoming link. A
titled `<fieldset><legend class="h6">Linked from</legend><div class="meta">…` panel listing up to 5
sources (chips) and "View all N" linking to `freelink/links?target=<id>`. No form inputs (so nothing
leaks into the host form). Sources the user cannot view are counted but not shown.

### Migration tools

The old template-routed `freelink/migrate` page becomes `freelink/migrations`: available sources
with field counts, a form per source (field handle optional, "Back up the database first",
**Dry run** default on) posting to `migrations/run`, the log of the last run (flash), and the
history table.

## 6. The link index and reverse lookups

`services\LinkIndex`:

- `indexValue(FreeLinkField, ElementInterface)` / `deleteFor(fieldId, ownerId, siteId)`
- `rebuild()` (synchronous, console) and `IndexLinks` (queue)
- `query(LinkQueryCriteria): LinkIndexResult` — the Links screen, the GraphQL query and MCP all use
  it. Criteria: `targetId`, `targetSiteId`, `fieldId|fieldHandle`, `type`, `siteId`, `sourceType`,
  `sectionId`, `domain`, `status`, `limit` (≤ 100), `offset`.
- `countFor(targetId)` — the panel.

`LinkReference` (model returned by the API): `sourceId`, `sourceSiteId`, `rootSourceId`, `fieldId`,
`fieldHandle`, `type`, `sortOrder`, `targetId`, `targetSiteId`, `url`, `label`, `status` (see §7),
`checkedAt`, `httpCode`, plus lazy `getSource()`, `getRootSource()`, `getTarget()`, `getField()`,
`getLink()` (the live `Link` model from the field value).

`Links::findLinksTo(ElementInterface $element, array $criteria = []): LinkReference[]` is the
public PHP API (the `links` service, as requested). Twig: `craft.freelink.linksTo(element, {…})`.
The pre-5.3 `craft.freelink.getRelatedElements()` keeps working (it reads `freelink_links`, includes
drafts/revisions' rows filtered to elements that load); its docs now point at `linksTo()`.

## 7. Link checks

### 7.1 Element links (database only, never fetched)

Computed in SQL at query time — always current, nothing stored:

| Status | Rule |
|---|---|
| `missing` | element link type, `targetId` null (target was hard-deleted → FK set null) or no `elements` row |
| `trashed` | target `dateDeleted` not null |
| `disabled` | target `elements.enabled = 0` or `elements_sites.enabled = 0` for the target site (`COALESCE(targetSiteId, ownerSiteId)`) |
| `pending` | target entry `postDate` in the future |
| `expired` | target entry `expiryDate` ≤ now |
| `live` | otherwise |

`problems` = anything but `live`.

### 7.2 URL links (HTTP, queue or console only)

Which links: index rows with a non-null `host` (http/https URL) — `url` and `custom` types (and any
custom link type whose URL is http/https). `site` links point at the site itself and are skipped.

Who triggers: `CheckLinks` queue job (CP button, `freelink:checkLinks`), `php craft
freelink/links/check [--force] [--limit=N]`, and the MCP tool only *queues* the job. Nothing checks
synchronously in a web request.

Selection: distinct `urlHash` from the live index whose check row is missing or older than
`recheckAfter` (unless forced), up to `maxChecksPerRun`, ordered by host then url so per-host delay
can be honoured.

Politeness: one request at a time (the job is single-threaded, so per-host concurrency is 1), a
`hostDelay` gap between requests to the same host, `User-Agent: FreeLinkChecker/5.3 (+Craft CMS
link checker)` — no site name, admin e-mail or other identifying data.

### 7.3 The SSRF guard (`helpers\SsrfGuard`, `services\Checker`)

For every request *and every redirect hop*:

1. **Scheme** must be `http` or `https`. No credentials in the URL (`user:pass@` → refused).
2. **Port** must be in `checkAllowedPorts` (default 80/443).
3. **Host**: lower-cased, trailing dot removed, IDN converted to ASCII.
   - IP literal (`[::1]`, `127.0.0.1`) → that address.
   - Non-canonical IPv4 forms that resolvers/curl accept — integer (`2130706433`), octal
     (`0177.0.0.1`), hex (`0x7f.1`), short forms (`127.1`) — are parsed with `inet_aton()` rules to
     the address they mean and checked as such.
   - Otherwise resolved with `dns_get_record(A + AAAA)` (and `gethostbynamel` fallback). No
     answer → `error`.
4. **Every** resolved address must be public; if any one is blocked the URL is `blocked` (defeats
   mixed-answer tricks). Blocked:
   - IPv4: `0.0.0.0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16` (incl. `169.254.169.254`),
     `172.16/12`, `192.0.0/24`, `192.0.2/24`, `192.88.99/24`, `192.168/16`, `198.18/15`,
     `198.51.100/24`, `203.0.113/24`, `224/4`, `240/4` (incl. `255.255.255.255`).
     Metadata `100.100.100.200` (Alibaba) and `169.254.170.2` (ECS) are inside these.
   - IPv6: everything outside `2000::/3`, plus inside it `2001::/23` (Teredo, benchmarking, ORCHID…),
     `2001:db8::/32`, `2002::/16` (6to4); and explicitly `::/128`, `::1/128`, `::ffff:0:0/96`
     (IPv4-mapped — the embedded IPv4 is also reported), `64:ff9b::/96` and `64:ff9b:1::/48`
     (NAT64), `100::/64`, `fc00::/7` (incl. AWS `fd00:ec2::254`), `fe80::/10`, `fec0::/10`,
     `ff00::/8`.
   - Exception: a host listed in `checkAllowedHosts` (config file) may resolve anywhere.
5. **Connect to the address that was checked**: curl `CURLOPT_RESOLVE host:port:ip` pins the
   connection, so a second DNS lookup (rebinding) cannot redirect it. IP literals are requested
   as-is. `CURLOPT_NOPROXY '*'` (a proxy would resolve the name itself),
   `CURLOPT_PROTOCOLS`/`REDIR_PROTOCOLS` = HTTP|HTTPS, `CURLOPT_FOLLOWLOCATION` off.
6. **Redirects** are followed manually, at most 5; each `Location` is resolved against the current
   URL and goes through steps 1–5 again. A redirect to a blocked target ends the check as
   `blocked` ("Redirects to a private address").
7. **Timeouts**: 5 s connect, 5 s total. **Byte cap**: the body is never stored; a GET reads at most
   64 KB (the write callback aborts beyond that). TLS verification on.
8. **Method**: `HEAD`; on 405/501/403/400 or a transport error, one `GET` (with the byte cap).

Statuses: 2xx → `ok` (or `redirect` when the final URL differs), 4xx/5xx → `broken` (429 →
`error`, "Rate limited"), transport failures/too many redirects → `error`, guard refusals →
`blocked`, checks disabled → nothing is fetched.

All HTTP goes through an injectable `HttpTransport` interface, so the guard and redirect logic are
unit-tested without a network; DNS goes through an injectable resolver for the same reason.

## 8. Per-link icons

- Field settings: `allowIcons` (bool, default false) and `includeProIcons` (bool, default false).
  Craft's bundled icon set includes Font Awesome **Pro** icons licensed for use in the Craft control
  panel; the field offers only the free icons unless `includeProIcons` is on (the setting's warning
  says the site needs its own Font Awesome Pro licence to show them on the front end) — the same
  choice Craft's own Icon field makes.
- Field UI: Craft's icon picker (`Cp::iconPickerHtml`, `freeOnly` as above) in each link block when
  `allowIcons` is on.
- Validation: `^[a-z0-9-]+$`, must exist in Craft's icon index; with `includeProIcons` off, must be
  a free icon.
- Stored as `icon` in the link JSON; dropped on normalise when the field has icons off (like custom
  attributes with Advanced off).
- Twig: `link.icon` (name), `link.iconSvg` / `link.getIconSvg({class: …})` → `Markup` of the SVG
  (from Craft's icon files, `aria-hidden="true"`, `focusable="false"`), `null` when there is none.
- API: `toApiArray()` adds `icon`; GraphQL `icon` and `iconSvg` fields; MCP via the field's MCP value.
- Migrators: none of the four sources (Hyper, Linkit, Typed Link Field, Craft Link) has a per-link
  icon; Hyper's are arbitrary custom fields, which FreeLink does not map. Nothing to preserve.

## 9. GraphQL

### 9.1 Output (`FreeLinkInterface`)

Added: `icon: String`, `iconSvg: String`, `elementId: Int`, `elementSiteId: Int`,
`elementType: String`, `subject: String` (email), `siteId: Int` (site links). The target element
object is *not* exposed (it would bypass the schema's element scope).

### 9.2 Mutations

`FreeLinkField::getContentGqlMutationArgumentType()` returns `FreeLinkInput` (single mode) or
`[FreeLinkInput]` (multi mode):

```graphql
input FreeLinkInput {
  type: String!          # link type handle, must be enabled on the field
  value: String          # url/email/phone/sms/custom/site path
  targetId: Int          # element link types; omit to keep the target already at this position
  targetSiteId: Int
  siteId: Int            # site links
  subject: String        # email links
  label: String
  newWindow: Boolean
  ariaLabel: String
  title: String
  urlSuffix: String
  classes: String
  htmlId: String
  rel: String
  icon: String
  customAttributes: [FreeLinkAttributeInput]
}
input FreeLinkAttributeInput { attribute: String!, value: String }
```

Values go through the same `normalizeValue()` and the same live-scenario validation as a CP save:
enabled types only (new in 5.3, applies to the CP too), per-type validation, unsafe schemes,
custom attribute names, icons, min/max links, required, selection conditions, and — new in 5.3 —
element targets must exist and be of the link type's element type. Element targets are additionally
checked against the **schema**: the target must be queryable by the schema making the mutation, so a
token cannot link to (and so reveal the URL/title of) an element it cannot read.

### 9.3 Reverse lookups

```graphql
freelinkLinksTo(elementId: Int!, siteId: Int, field: String, type: String,
                limit: Int = 20, offset: Int = 0): [FreeLinkReference]

type FreeLinkReference {
  sourceId: Int!  sourceSiteId: Int!  rootSourceId: Int!
  source: ElementInterface        # the root owner, as the schema may read it
  field: String!  type: String!  position: Int!
  link: FreeLinkInterface
}
```

- Registered only when the schema has the **FreeLink → Query reverse link lookups**
  component (`freelinkLinks:read`).
- The *target* must be queryable by the schema (else empty list — no existence oracle).
- Each *source* (root owner and, for nested entries, the owner) is re-queried through Craft's own
  element GraphQL resolver for its type (`craft\gql\resolvers\elements\<Type>::prepareQuery(null, …)`),
  which applies the schema's section/volume/group scopes, live-status default and authenticated
  user's view rights. Sources the schema cannot query are dropped. Element types without a known
  resolver are dropped (fail closed).

## 10. MCP surface (Craft 5.12+)

Registered only when `craft\mcp\CapabilityRegistry` exists (Craft ≥ 5.12), so FreeLink still runs
on Craft 5.0–5.11. Tool names follow the shared plugin convention (`<handle>_<verb>_<noun>`); see
`plugin-testing-craft6/porting/mcp.md` for the cross-plugin rules.

| Tool | Gate | Does |
|---|---|---|
| `freelink_find_links_to` | `freelink:viewLinks` | reverse lookup for an element id (same criteria as §6), sources filtered by the MCP user's `canView` |
| `freelink_list_links` | `freelink:viewLinks` | the Links screen query (filters, limit ≤ 100, offset) |
| `freelink_check_links` | `freelink:viewLinks` (report) / `freelink:checkLinks` (`queue: true`) | broken-link report from **stored** results + element status; can *queue* a check job; never fetches |
| `freelink_migration_status` | admin | available sources + history |
| `freelink_migrate` | admin + allowAdminChanges | run a migration; `dryRun` defaults to **true** |

Field values: `FreeLinkField` implements `InputSchemaFieldInterface` (`getInputSchema()` → JSON
schema of `FreeLinkInput`, single or list) so core's element create/update tools write FreeLink
fields, and `McpOutputFieldInterface` (`getMcpValue()` → `toApiArray()` per link) so reads return
resolved links. Both interfaces are referenced by name only when they exist.

## 11. Twig and PHP API

```twig
{{ link.icon }} {{ link.iconSvg }} {{ link.getIconSvg({class: 'w-4 h-4'}) }}
{% for ref in craft.freelink.linksTo(entry, {field: 'cta', limit: 10}) %}
  {{ ref.source.title }} — {{ ref.fieldHandle }} — {{ ref.link.text }}
{% endfor %}
{{ craft.freelink.linkCountTo(entry) }}
```

```php
use justinholtweb\freelink\Plugin as FreeLink;
$refs = FreeLink::getInstance()->links->findLinksTo($entry, ['field' => 'cta']);
```

(`craft.freelink` is now registered on Craft's variable; before 5.3 only the global `freelink`
existed, so the README's `craft.freelink.getRelatedElements()` example did not work. Both work now.)

## 12. Security notes

- Fetching: only stored link URLs; SSRF guard on every hop; pinned connections; no proxy; byte cap;
  timeouts; UA without personal data; admin kill switch; private-host allowlist only from the
  config file.
- Request input never reaches the fetcher: CP actions take no URL, only "queue a check of what is
  stored"; GraphQL has no check mutation; MCP's check tool only reads stored results or queues.
- Every CP action: `requirePermission`/`requireAdmin`, `requirePostRequest` + CSRF for writes.
- SVG nav icon: sanitised on every render (`Html::svg(sanitize: true, namespace: true)`), validated
  to be an `<svg>` element on save.
- Links screen and panel hide sources the user cannot view (`canView`), but still count them.
- GraphQL: target and sources filtered by schema scope (see §9). Mutations enforce enabled types,
  existing targets, and schema-readable targets.
- Rendered URLs on the Links screen go through `Link::getUrl()` (unsafe schemes already null) and
  are output escaped with `rel="noopener noreferrer"`.

## 13. Craft 6 porting notes

- Tables and JSON are framework-neutral; port the migration as-is (`freelink_index`,
  `freelink_checks`, `icon` key).
- `SsrfGuard`, `IpRanges` and the checker's redirect loop have no Craft dependencies other than
  the transport interface; port them verbatim with their unit tests.
- Sidebar customisation: in Craft 6, prefer the core nav editor; keep the settings for parity (the
  Caffeine 6 port keeps `navLabel`/`navIcon`/`navIconSvg` with the same semantics).
- MCP: Craft 6 registers capability classes the same way; tool names and gates above are the
  contract.
- Element sidebar panel: Craft 6's element edit screen event replaces `EVENT_DEFINE_SIDEBAR_HTML`.
